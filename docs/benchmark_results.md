## Peeking (10 looks, alpha = 5%)

| Rule | False positives (no effect) | Power (+15% lift) | Avg. sample used (lift) |
|---|---|---|---|
| Test once at the end | 5.3% | 69.3% | 100.0% |
| Peek, stop at first p < 0.05 | 20.9% | 79.2% | 56.4% |
| Group-sequential (O'Brien-Fleming) | 5.2% | 66.6% | 81.4% |
| Always-valid mSPRT | 0.3% | 26.7% | 93.7% |

Reading the peeking table: naive peeking looks powerful only because it cheats (4x the promised false-positive rate). Group-sequential keeps the 5% guarantee at nearly the fixed-horizon power. The always-valid mSPRT is valid at *any* stopping time without a pre-planned schedule, but pays for that flexibility with much lower power; prefer group-sequential when a maximum sample size is known.

**PyMC cold start** (fresh process, warm disk cache): the first request, which imports PyMC and compiles the model, takes 2.9 s; later models take 1.5 s. On a cold disk the first request in this project's environment took 10 to 13 s. Set `ABLAB_WARMUP_PYMC=true` to pay this at server start instead of on the first user request; the closed-form engine answers in milliseconds.

A light endpoint (sample-size calculation) sustains about 111 requests per second per core. Timings come from a shared single core and vary by up to about 2x between runs; treat them as orders of magnitude.
